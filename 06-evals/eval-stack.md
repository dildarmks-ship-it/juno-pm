## What "good" means

>=85% thumbs-up; reopen rate <=8%

- Active: thumbs up/down per answer; explicit "wrong policy cited" report
- Passive: ticket reopened within 24h, manager escalation rate

## The stack

| Layer | Evaluator | What it catches | Threshold / gate |
|---|---|---|---|
| Code-based | Automated checks · cadence: Every PR + nightly + post-policy-update · owner: CI gates the PR. Eng owns infra. PM owns policy-accuracy bar. | - LLM-judge: policy accuracy + tone - Citation check: every claim links to a real policy doc - PII filter: must redact employee names/IDs - Refusal check: legal/medical questions => refer to live HRBP | >=95% policy accuracy; 100% PII/refusal/citation pass |
| LLM-as-judge | Automated assessment on the golden set | Silent wrong outputs at the long tail | >=95% policy accuracy; 100% PII/refusal/citation pass |
| Human | 06-evals/human-rubric.md (HR variant) · 2 HRBPs + PM tiebreak · cadence: Weekly batch (every Mon) | - 80 conversations / week - Stratified by policy domain (vacation, comp, parental leave, conduct) - 100% of escalations included | >=4.5/5 on policy accuracy; 0 wrong-policy citations |

## Golden set

- 300 anonymised HR Q&A pairs (versioned, refreshed quarterly)
- Cover all 12 policy domains

## Release gate

**Hard gates (auto-block):**

- 0% PII leakage
- Wrong-policy citation => auto-block
- Refusal-check fail => auto-block

**Soft gates (PM sign-off):**

- P95 latency >3s requires HR Ops PM sign-off

**User-feedback layer (online):** cadence Per request + weekly aggregate; owner HR Ops PM reviews weekly; auto-Slack on >=3 reopens for same policy in 7d.
