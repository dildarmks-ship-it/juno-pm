## Goal

Book a movie ticket for the user within their stated parameters, saving them the search-and-checkout time (delight) while never charging without approval (risk).

**Primary actor:** Agent + Human-in-the-loop

## Trigger

Command - Book
Steps and Testable conditions
1. Human to start with the Goal asking to book a movie ticket
2. Provide following information for the Agent to processing:
- which movie
- how many tickets
- specific date
- specific time of the show
Control back:
- If the theater is full
- Movie is not showing
- Movie timing is not matched
- Payment failed
- Payment Card expired
- Payment details not on file

## Steps & tools

**Pattern:** ReAct (single-agent reason-act-observe loop)

**Schemas**

kb.retrieve → {chunks:[{text, source, score}]}
user.get_profile → {user_id, home_location:{lat,lng}, preferred_theaters:[], seat_pref, notify_channel}
theaters.search → {results:[{theater_id, name, distance_miles, showtime_id, start_time, price_per_ticket, seats_available}]}
theaters.get_seats → {showtime_id, seats:[{seat_id, row, status}]}
booking.reserve → {booking_id, status: confirmed|failed, seats:[], total, error?}
payment.get_method → {payment_token, last4, expiry_status: valid|expired|missing}
payment.charge → {transaction_id, status: success|declined|error, amount}
email.send / sms.send → {message_id, status: sent|failed}
calendar.create_event → {event_id, status}

**Memory (in or out of scope)**

- **Episodic:** In-scope. The sequence of actions for this booking run: the parsed request, clarifying questions asked and answers received, theaters/showtimes searched and results returned, the user's approval decision, payment attempt result, booking confirmation ID, and notification/calendar status. Lifetime: end of run (retained 30 days in an audit log for support disputes only).
- **Semantic:** In-scope: user's preferred theaters, seat preference (aisle/center), preferred showtime window (e.g. evenings after 7pm), preferred notification channel (email vs SMS), and the $200 approval threshold. Lifetime: indefinite, until the user edits preferences. Out of scope: do NOT persist full payment card numbers, CVV, or card expiry — only a tokenized payment reference held by the payment provider. Do not persist details of other users' bookings.
- **Working:** In-scope, live for this run only: current request (movie title, ticket count, date, time), user ID and home location/20-mile radius, retrieved booking-strategy KB chunks, list of candidate theaters and showtimes with prices, selected showtime and seats, running total cost vs $200 threshold, and the pending approval state.
- **External:** Booking Strategy KB (read), Theater/Showtime search API (read), Theater booking API (write, booking only), Payment provider API (read tokenized details, write charge — only after user approval), Email API (write), SMS API (write), Calendar API (write, create event only).

## Human-in-the-loop

Human is involved when:
- If the theater is full
- Movie is not showing
- Movie timing is not matched
- PM approves any amount above 200 dollars
- Payment failed
- Payment Card expired
- Payment details not on file

## Success & failure

- **Done when:** 1. SUCCESS: Ticket booked, confirmation ID received from theater API, email + SMS sent, calendar event created → agent stops and reports confirmation.
2. FAILURE: No showtime matches movie/date/time within 20-mile radius, or theater is full, or movie not showing → agent stops and reports options to user.
3. ESCALATION: Total cost > $200, payment failed, card expired, or payment details not on file → hand back to user for decision/approval before any booking.
4. TIMEOUT: No user response to a clarifying question or approval request within 15 minutes, or theater/payment API not responding after 3 retries → agent stops, no booking made, user notified.
5. MISSING INFO: Required parameters (movie, ticket count, date, time) still missing after 2 clarifying questions → hand back to user.
- **Fails safe when:** Agent can READ: booking strategy KB, user profile/preferences, theater search + seat availability, tokenized payment method status.
Agent can WRITE: reserve a booking (only after explicit user approval), charge payment (only after approval; auto-approve ≤ $200, above requires human approval), send email/SMS confirmation, create a calendar event.
Agent CANNOT: view or store raw card numbers/CVV, add or edit payment methods, modify or delete existing calendar events, cancel or refund bookings, or book without user approval. All writes are logged with user_id and timestamp for audit.
